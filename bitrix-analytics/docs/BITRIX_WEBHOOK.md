# Как создать вебхук в Битрикс24

Вебхук — это «ключ доступа», по которому наша система читает данные CRM. Создаётся один раз за несколько минут.

## Шаги

1. Зайдите в свой Битрикс24 **под администратором**. Вебхук видит ровно то, что видит его владелец, поэтому сделки, к которым у владельца нет доступа, в аналитику не попадут.
2. Откройте **Разработчикам → Другое → Входящий вебхук**. В старом меню это *Приложения → Ресурсы для разработчиков → Другое → Входящий вебхук*.
3. Нажмите **Добавить вебхук** (или «Вебхук для API вызова REST»).
4. В списке прав отметьте:
   - **CRM** (`crm`): сделки, воронки, стадии, история стадий;
   - **Пользователи** (`user` или `user_basic`): имена менеджеров.
5. Сохраните. Битрикс покажет **«URL для вызова REST»**, примерно такой:

   ```
   https://ваш-портал.bitrix24.ru/rest/1/abcd1234efgh5678/
   ```

6. Скопируйте его целиком, **вместе с завершающим `/`**, и вставьте в файл `.env` в строку `BITRIX_WEBHOOK_URL=`.

## Безопасность

- Код в конце ссылки работает как пароль. Кто его знает, может читать данные вашей CRM.
- Не отправляйте ссылку в чаты, не вставляйте её в код и не загружайте файл `.env` в git (он в `.gitignore`).
- Если ссылка попала не туда, откройте вебхук в Битрикс24 и нажмите **«Пересоздать»** или удалите его и создайте новый. Затем обновите `.env` и перезапустите: `docker compose up -d`.

## Что система читает

Только методы чтения: `crm.deal.list`, `crm.category.list`, `crm.status.list`, `crm.stagehistory.list`, `crm.deal.userfield.list`, `user.get`. Данные в Битрикс24 система не меняет.

## Лимиты

Облачный Битрикс24 разрешает в среднем около 2 запросов в секунду. ETL выдерживает паузу 0,5 с между запросами и сам повторяет запрос, если Битрикс отвечает «слишком часто». Первая полная выгрузка большой CRM (десятки тысяч сделок) может идти несколько десятков минут, это нормально.
