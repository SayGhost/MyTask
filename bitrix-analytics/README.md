# Bitrix24 Analytics

Своя система аналитики на данных облачного Битрикс24: сборщик (ETL) складывает CRM-данные в PostgreSQL, на них строится дашборд.

```
Битрикс24 (облако) ──REST, входящий вебхук──▶ ETL (Python, раз в 10 мин) ──▶ PostgreSQL ──▶ Дашборд
```

## Что хранится в БД

| Таблица | Содержимое |
|---|---|
| `fact_deal` | Сделки: воронка, стадия, сумма, менеджер, источник, UTM, даты создания, изменения и закрытия, пользовательские поля (`user_fields`, JSON), полный ответ Битрикса (`raw`). Удалённые сделки не стираются, а получают `is_deleted = true` |
| `fact_stage_history` | Каждый переход сделки между стадиями со временем. Нужна для воронки и атрибуции по дате перехода |
| `dim_category`, `dim_stage`, `dim_source`, `dim_deal_type` | Воронки, стадии (`semantics`: `S` успех, `F` провал), источники, типы сделок |
| `dim_user` | Сотрудники |
| `dim_userfield` | Пользовательские поля сделок с подписями и значениями списков |
| `sync_log`, `sync_state` | Журнал запусков и отметки инкрементальной загрузки |

Даты хранятся в UTC (`timestamptz`). `close_date` у открытых сделок — плановая дата, а не фактическая.

## Как работает синхронизация

- Первый запуск: полная загрузка всех сделок и истории стадий.
- Далее каждые `SYNC_INTERVAL_MINUTES` минут: сделки, изменённые после последней отметки `DATE_MODIFY` (с запасом 10 минут), и новые записи истории стадий. Загрузка идемпотентна (upsert), поэтому повторы и перезапуски безопасны.
- Раз в сутки ночью: сверка списка ID, удалённые в Битриксе сделки получают пометку `is_deleted`.
- Справочники перезагружаются целиком каждый цикл.
- Каждый шаг пишет результат в `sync_log`. Ошибка одного шага не останавливает остальные.

## Разработка

```bash
cd etl
pip install -r requirements-dev.txt
python -m pytest                      # без БД тесты Postgres пропускаются
TEST_DATABASE_URL=postgresql://user:pass@localhost:5432/test_db python -m pytest   # полный прогон; БД будет очищена!
```

Тесты используют поддельный сервер Битрикс24 (`etl/tests/fake_bitrix.py`) и не обращаются к настоящему порталу.

Команды ETL: `python -m app.main` (постоянная работа), `--once`, `--once --full`, `--reconcile`. Новые миграции кладите в `etl/app/migrations/NNN_name.sql`, они применяются автоматически при старте.
