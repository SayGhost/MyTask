# Аналитика: дашборды по выгрузке Битрикс24

Работает **только на вашем компьютере**: данные из выгрузки не отправляются в интернет. Готовы дашборды «Общий» и «Маркетинговый»; «Отдел продаж» и «Доступы» помечены «скоро».

## Запуск

1. Установите Python 3.9 или новее: https://www.python.org/downloads/ (на Windows отметьте «Add python.exe to PATH»). Больше ничего ставить не нужно.
2. Положите в папку `data` CSV-выгрузки сделок из Битрикс24: **воронки «Консультанты»** (нужна для обоих дашбордов) и **воронки «Продажи»** (нужна «Общему» для МС проведено, SL и покупок). Какая это воронка, определяется по колонке «Воронка». Если файлов одной воронки несколько, берётся самый свежий.
3. Запустите `start.bat` (Windows) или `bash start.sh` (Mac/Linux). Откроется браузер на http://127.0.0.1:8765.
4. Новая выгрузка: замените файл в `data` и нажмите «Обновить» на странице.

Остановить: закройте окно или нажмите `Ctrl+C`.

## Что в «Общем» дашборде

Показывает путь от лида до покупки по обеим воронкам. Главная идея: каждый этап считается **потоком по дате самого события**, и для него показано, **из каких лидов** он пришёл: «из лидов периода» и «из прошлых». Лид может стать квалом или купить через недели после создания, поэтому за неделю квалов бывает больше, чем дошло от свежих лидов этой недели.

- **Пульс периода:** лиды (новых и повторных), квалы, записались на МС, МС проведено (и сколько ожидают впереди), стали SL (ушли, чистый прирост, сейчас в SL), покупки с суммой и средним чеком. У каждой карточки есть полоска «доля из лидов периода», изменение к прошлому периоду и график за 12 недель.
- **Поток по неделям:** столбцы по каждому этапу, окрашенные по дате создания лида (этой недели, прошлой, более старые). Есть режим «Таблица».
- **Когорты:** строка это неделя создания лидов, столбец это «через сколько недель случилось событие». Видно, как быстро лиды доходят до этапа и какие недели ещё «дозревают». Переключается между квалами, записью на МС, МС проведено и покупками, в процентах и штуках.
- **МС:** записаны и проведены за период, ожидают впереди (и на ближайшие 7 дней), «зависли» (дата МС прошла, МС не проведена). Карточка «Из чего сложилось «МС проведено»» раскладывает все сделки с датой МС в периоде на «посчитано» и «не посчитано» по стадиям и причинам: по ней можно сверить число со своим подсчётом.
- **SL:** стали и ушли по неделям, сейчас всего, у скольких нет даты входа.
- **Продажи:** покупки, сумма, средний чек, дней от создания лида до покупки, доп. продукт, выручка по группам источников.
- **Материалы:** что довело до SL и после чего закрыли на МС (поля новые, пока заполнены мало).
- Фильтры: период и сравнение, группы источников, тип сделки «Все / Новые / Повторные».

### Как считается «Общий»

| Событие | Откуда | Дата события |
|---|---|---|
| Лид | «Консультанты» | «Дата создания» |
| Квал | «Консультанты» | «Дата квала» |
| Записался на МС | «Консультанты», статус «МС назначена» | «Дата завершения» (в выгрузке колонка «Предполагаемая дата закрытия»: у закрытых сделок это и есть дата завершения) |
| МС проведена | «Продажи» | «Дата и время МС (квал)», не в будущем; стадия «3 Сопровождение на доп» и дальше. У стадии «Отказ» МС тоже проведена, если причина отказа не из списка «МС не состоялась» (см. `settings.py`) |
| МС ожидает / зависла | «Продажи», стадии «0 МС назначена», «1 Ждет перезнаначения» | Дата МС впереди / уже прошла |
| Стал SL / ушёл из SL | «Продажи», «SL лид» «Да» / «Нет» | «Дата изменения SL лида» |
| Покупка / доп. продукт | «Продажи», стадия «Передан на обучение» / «8 Купил Доп.Продукт» | «Дата завершения», сумма из «Сумма» |

Группа источников, источник и UTM у копий в «Продажах» берутся из самой копии (там они продублированы). Связь копий с исходными сделками пока не нужна и не используется. В периоды не попадают события с датой раньше создания лида (ошибка данных, например унаследованная дата): их число показано в предупреждении внизу страницы.

Ограничения: «SL лид» хранит только последнее состояние, поэтому история «стал, потерял, снова стал» теряется. SL без даты входа считаются только в «Сейчас в SL». Точная история всех переходов появится после подключения Битрикс24.

## Что в маркетинговом дашборде

Атрибуция по **дате создания лида**. Источники сведены в 4 группы: «Вебинарные», «Практикум», «Мини-продукты», «Другое».

- **Период и сравнение:** пресеты (эта и прошлая неделя, этот и прошлый месяц, 30 дней, всё время), свои даты, сравнение с предыдущим периодом, с прошлым годом или со своим периодом. У каждой карточки показано изменение и значение «было».
- **Карточки:** новые лиды, посетили мероприятие (с процентом от лидов), дозвонились, квал (процент из дозвонившихся), МС назначено (процент из квалов). Под числом мини-график последних 12 недель.
- **Что изменилось:** главные сдвиги объёмов и конверсий к периоду сравнения.
- **Путь лидов** по этапам, **лиды по группам источников** во времени, таблица по группам, **конверсии по неделям**.
- **Дерево UTM:** source → medium → campaign → content → term, с теми же метриками; цвет строки показывает число лидов.
- **Причины отказа** (график и дерево по UTM), **заявки на МС** по UTM.
- **Скоринг** за 12 недель и 6 месяцев: «Оценка: все шкалы» (старая A–F серым и новая звёздная синим на одном графике, видно момент перехода), отдельно звёзды и A–F, а также балл, сегмент, эксперты, новички, «для себя». Если у лида есть обе оценки, берётся звёздная. Старые оценки A–F сохраняются.
- Две темы оформления: тёмная «стекло» и светлая. Переключатель внизу экрана.

### Как считаются показатели

| Показатель | Правило |
|---|---|
| Новые лиды | «Тип сделки» = «Новая» (галочка «Включать повторные сделки») |
| Посетили мероприятие | заполнена «Посетил вебинар»; доходимость = посетили / лиды |
| Дозвонились | статус («Статус сделки fix») начинается с `91 `, `92 `, `93 ` или это «МС назначена»/«БК назначена»; **либо** сделка провалена, а причина отказа не из списка «не дозвонились» (не вышел на связь, неверный номер, номер другого человека, отказ от диалога сразу после приветствия, слив базы; префикс «МЛ » не учитывается) |
| Квал | заполнена «Дата квала»; процент = квал / дозвонились |
| МС назначено | заполнена «Дата и время МС (квал)»; процент = МС / квал |
| Заявки на МС | заполнена «Оставил заявку на МС» |

Все проценты считаются из тех же чисел, что показаны на карточках, поэтому сходятся «на калькуляторе». Свежие лиды (последние 7 дней) ещё не успели дойти до этапов, поэтому проценты за последние дни занижены: страница предупреждает об этом, а на графиках конверсий неполная неделя не рисуется.

## Приватность

- Адрес `127.0.0.1` доступен только на этом компьютере. Страница ничего не загружает из интернета, браузеру это запрещает заголовок безопасности.
- Читаются **только колонки из `settings.py`**. Телефоны, почты, имена и комментарии в память не загружаются и в браузер не попадают.
- Файлы `*.csv`, `*.xlsx` и папка `data` исключены из git (`.gitignore`).
- Если что-то сломалось, присылайте текст ошибки, а не файл.

## Настройки: `settings.py`

Один файл, в нём всё с комментариями:
- названия колонок выгрузки обеих воронок;
- правила групп источников (по фрагментам названия);
- список статусов и причин отказа для «Дозвонились»;
- диапазоны числового балла скоринга;
- правила «МС проведена»: стадии, причины отказа, при которых МС не состоялась, и признаки в «Итоге МС» (`MC_NOT_HELD_REASONS`, `MC_NOT_HELD_RESULT_PREFIXES`, `MC_HELD_STAGES`);
- стадии покупки и доп. продукта.

Если колонки не найдены, страница покажет, каких именно. Необязательные колонки (UTM, скоринг, заявка на МС) можно не иметь: соответствующие блоки будут пустыми.

## Дальше

Эта же страница будет получать данные из базы PostgreSQL, которую наполняет сборщик из Битрикс24 (папка `etl`). Расчёты в `static/metrics.js` от источника данных не зависят. Раздел «Доступы» (роли: администратор, команда, подрядчики; выдача и отзыв доступа) появится при переходе на сервер.

## Для разработки

```bash
python3 -m pip install pytest
python3 -m pytest                       # загрузчик, правила, сервер
node --test tests/metrics.test.js       # расчёт метрик
python3 tests/synth.py demo.csv         # выдуманная выгрузка для проверки внешнего вида
python3 server.py --file demo.csv
```
